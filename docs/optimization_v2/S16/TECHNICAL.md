# S16 技术原理与实现边界

本步检验“重复运动情境能否减少计算”，默认配置 `enabled: false`。命中仅推荐实时 IMM，不返回旧轨迹、旧绝对位置、车辆速度或通行许可。S15 当前预测候选尚未通过默认启用资格；本步实验不能改变这个结论。实际结果见同目录 RESULTS.md。

## 数据流与算法

S09 带噪声、融合语义的目标观测，加 S05 局部里程计和 S08 定位状态，进入 S16 适配器。在线只订阅 ROS 域 119，不读仿真 actor 脚本或域 120 真值。沿用 S15 八个历史状态、0.4 s 网格、3.2 s 预测跨度；观测按到达时间维护，历史差分不读取未来。

上下文为 17 维：三维尺寸、近期/较早速度、加速度、邻近目标距离、协方差最大特征值对应标准差、视觉类别置信度、运动相对车辆前进方向、横向相对距离、邻居数量、自车速度/角速度。类别和 STOP/CROSS/ALONG 作为离散门控。定位许可、时间新鲜度、目标实时净距额外硬门控。道路关系当前是**自车前向走廊代理**，没有声称实现地图语义车道或成熟道路关系识别；这是下一阶段真实复杂路口评估的局限。预测质量使用训练窗口的 IMM 误差准入及当前跟踪不确定性，不把网络置信度当已校准碰撞概率。

过去速度转换到当前车体朝向，再比较方向余弦；相同外形、相反运动不得命中。轨迹 ID 只用于当前跟踪/事件状态，失踪后清空，不进入特征向量或永久身份。SQLite 的 provenance 可记录训练窗口来源用于审计，不能据此决定在线命中。

原型只来自 S15 **train 完整场景**。离线后续观测用于比较 IMM 与学习模型；IMM 加权 ADE ≤0.30 m 且不差于学习模型，才候选入库，再应用当前质量/净距准入。验证/测试标签不写入库。冻结参数后重复测量，未根据测试结果放宽门限。测试分割沿用 S15 小样本仿真集，并非跨城市或真实环境泛化证明。

检索为最多 256 条原型的精确扫描。距离为 `sqrt(mean(((feature-prototype)/scale)^2))`，门限 0.65；门限属于本实验工程初值，不声称统计最优。方向余弦至少 cos45°，观测和定位时效 ≤0.3 s，跟踪标准差 ≤0.25 m，速度 ≤2 m/s，加速度 ≤2 m/s²，当前净距至少 2 m。近距离、突变、过期、版本不符、OOD、查询超时等均回退重模型；失效预测再由原 S15/S14 层回退基础几何安全。

事件触发只用当前和过去：新历史、距离上次事件达到 1.2 s、速度变化 ≥0.15 m/s、运动模式变化、当前冲突或定位质量下降。非事件帧仍计算当前 IMM，**不保持上一帧学习轨迹**。缓存只替代事件帧的模型选择；所有输出继续进入原 S15 C++ 风险评估和 S14 BT、唯一底盘门。三组在线均使用同一个运输适配器，无额外 cmd_vel 出口。

## 三组消融与计时

- full：每个可预测观测帧调用真实锁定 Trajectron++；非行人沿用 IMM。
- event：同一事件规则调用重模型，其余帧实时 IMM。
- cache：相同事件规则；命中且 C++ 准入通过时用当前 IMM，否则重模型。

同一冻结验证/测试观测各重复三次，组顺序循环轮换，初始 SQLite 文件 SHA 完全相同；逐目标事件序列 SHA 应三组一致。输入观测和定位日志逐文件冻结。模型预热不计入稳态，数据库复制/模型装载属于初始化，不冒充稳态在线耗时；整个评估器墙钟另列，含离线评分不能解释为在线延迟。

在线核心总计时包括滤波更新、历史/上下文特征、检索、SQLite 提交维护、实时模型预测和组装；单独列出各部分墙钟。CPU 使用 process_time，延迟使用 perf_counter；原节点还记录请求到结果的运输耗时，实际 Gazebo 记录整个自有进程组 CPU/RSS 和任务仿真时间。模型固定 CPU 单线程，GPU 推理为 N/A，Gazebo GPU 负荷不算模型节省。不能把减少调用数等同总计算收益。

准确性使用后续**观测**作标签，不是理想真值；输出加权 ADE/FDE、95% 混合矩椭圆覆盖。误命中定义为已评分命中窗口的 ADE 比同刻 event 组高出 0.02 m；没有未来标签的窗口不参与，分母必须同时显示。闭环四类场景各三组，固定两点作业；不是完整簇或六簇验收。接近风险沿用 S15 当前足迹与未来观测代理，零暴露时标 N/A，不能声称漏风险率为零。

启用需 CPU 净收益至少 5%、误命中不超过 5%、至少 20 个可评分命中、误差和任务时间无明显退化、独立安全正常且有冲突暴露，并且上游预测方案已合格。任一不足，建议 disable；实验正常完成仍可以 S16 PASS。

## 有界持久化

在线库总预算为十进制 **100,000,000 字节**，主数据库页数只使用不到一半预算，给 DELETE 回滚日志与页头留余量；不是仅给主文件设置 100 MB 却忽略 WAL。单原型上限 4096 字节、默认最多 256 条，审计最多 256 条；另存累计淘汰数。满时按 last_used、key 稳定淘汰；TTL 7 天，质量每 2 天减半，低于 0.5 拒绝。在线按有界批次淘汰过期项。schema、地图绑定、模型配置绑定和特征版本都参与失效。墙钟回退拒绝，重启不能续命 TTL。

SQLite 使用 FULL 同步事务，锁争用/损坏/磁盘拒写回退当前推理，不依赖数据库保证避障安全。生产上限和缩小预算的压力测试分别记录；压力测试验证同一淘汰代码，不假称已写满 100 MB。保留小型指标、短观测证据，不增加无限视频记录。

官方依据：[SQLite PRAGMA](https://www.sqlite.org/pragma.html#pragma_max_page_count) 说明最大页数约束；[SQLite VACUUM](https://www.sqlite.org/lang_vacuum.html) 说明删除后页面可复用且完整 VACUUM 需要额外空间，因此本实现不在驾驶循环中运行 VACUUM。

## 优点与代价

轻量、可解释、版本可审计、无需另加视觉网络；能直接回答命中或拒绝原因。代价是查询和 fsync 可能抵消小模型节省；精确扫描只适合小库；方向/场景特征不等于物体身份，也不能保证未来行为相同。当前基准可否定收益，不能证明所有商用环境均无价值。

## 本轮数据给出的解释

正式冻结回放中，三次测试集重复合计的预测链 CPU 时间为 full 23.144 s、event 21.392 s、cache 20.820 s。缓存相对同事件基线只减少约 **2.67% CPU / 1.37% 墙钟**，低于预设 5% CPU 门槛。重模型调用从 1206 减到 1113，但查询约 79.9 ms、同步维护约 321.7 ms，以及共用特征/滤波开销都会抵消收益。93 次原始命中包含三次重复；只有 6 个可评分的独立采样命中，0 次误命中仍不足以支持泛化结论。

同一正式闭环中，转向场景 cache 65.251 s 比 event 79.047 s 快；让行场景却从 event 63.75 s 变为 cache 82.71 s，约慢 29.7%。两者均包含停车收尾且完成 2/2 点。这表明更便宜的实时 IMM 可能改变风险包络和等待时机，计算上的节省不保证作业更快。该解释只针对本轮短基准，不是六簇或真实农田验证。

默认关闭的依据同时包括算力净收益不足、可评分命中样本不足和上游 S15 预测策略尚未合格；没有为得到正收益而调松相似度、净距或停车门限。
