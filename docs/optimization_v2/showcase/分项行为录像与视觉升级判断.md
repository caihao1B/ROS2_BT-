# 分项行为录像与视觉升级判断

结论：**适合进入短场景、逐项行为录像；适合先做一轮轻量视觉升级。尚不适合宣称完整自主作业、全部动态场景可靠或商用性能通过。** 不需要为了录下一个避障行为而完成六簇或反复追求 95% 覆盖率。

本次是基于已有实测记录的准备度判断和后续范围说明，没有启动新仿真、重置旧录制预算、降低正式 S17 标准，也没有把方案文档当作新增功能已经运行。当前仍是 S17 PARTIAL，S18 未执行。

## 逐项准备度

用户已明确：跟随前方同向移动障碍物保持距离，同时沿原任务通道行驶。目标离开通道后确认前方清空，再恢复任务；横穿障碍按停让处理。目标丢失或身份不确定时停车，不能追出工作区。

阿克曼巡检 `215213` 中有 16 次**演员自身停让**事件，但机器人决策记录没有对应的 SHORT_OBSTRUCTION_WAIT。不能用“障碍物让开了”作为机器人独立避障成功的证据。差速巡检 `212812` 存在航向验收失败，不用于包装稳定导航成功。

## 新录像的成功标准

录像从行为触发前开始，连续保留检测、决策、执行和反馈。需要有：有效传感器与定位；真实障碍感知；行为原因；实际速度/停车反馈；无接触、无越界；工具状态；残余账本。定位失效造成的停车应按定位保护展示，不改名为避障。

长期障碍可以导致未达到 95%：展示结果记为“本行为已展示”，任务仍记为“部分完成/安全结束/需要人工检查”，公布原分母上的实际覆盖率和未完成区域。禁止为了录像将障碍区域偷偷从分母删除、把跳过任务算已完成，或把安全报警伪装成成功绕行。正式任务的原 95% 标准保留。

建议六个独立片段：正常跟踪作业；短时障碍停车恢复；前方移动障碍距离跟随；有可行绕行时换路；长期阻塞安全停止；有效作业反馈与残余说明。每片以 1–3 分钟成片为目标；关键交互保留 1× 实速，必要的接近路段可明确标注倍速。正式录制前，每种行为只做一次有界短测，失败则修该行为，不重跑全部六簇。30–60 分钟现实运行是初步录制预算目标，不是已经测得的耗时承诺；旧 179.2 分钟账本保持原样，后续新批次单独版本化记账。

## 视觉可以升级到什么程度

建议先做“精细的轻量工程模型”，而非全场景影视级重建：

- 两种车增加机壳、倒角、轮毂、橡胶轮胎、传感器外壳、急停按钮、灯组和工具罩；区分喷洒车与割草车的用途，但不伪造真实机械臂执行。
- 地面增加草地、泥土、碎石和道路的平铺纹理；用贴图与法线表达细节，避免满地高密度草叶。
- 障碍替换为辨识度更高的石块、低矮箱体、树桩、围栏和设备外观；行人采用轻量人体外形，后续再加合适动画。
- 使用适度光照、阴影和清楚的第三人称镜头；规划路径、任务区和告警采用清晰叠加层。

Gazebo Harmonic 支持 PBR 材质；官方建模方法也明确区分简单碰撞几何和精细视觉网格。优先保持质量、惯量、轴距、关节、碰撞体、摩擦与传感器安装不变，通过独立 visual 材质/网格增强外观。[Gazebo Harmonic 功能表](https://gazebosim.org/docs/harmonic/comparison/)、[Gazebo Sim 8 建模与网格优化](https://gazebosim.org/api/sim/8/model_and_optimize_meshes.html)

但**只改 visual 仍不等于算法输入完全不变**：RGB 相机会看到新材质，GPU 雷达也能看到视觉网格；本项目恰好使用 GPU LiDAR。因此新网格不能随意超出碰撞包络，不能挡住传感器。更换行人外形时也须保留原运动和碰撞代理；Gazebo 的标准动画 actor 本身不受接触力作用，不能直接把原障碍模型换成 actor 后仍声称碰撞测试有效。[Gazebo Harmonic Actors](https://gazebosim.org/docs/harmonic/actors/)

视觉预检建议控制为一个 2–5 分钟的独立短场景：核对模型比例与碰撞包络、传感器视野、点云/图像、定位准入、停车反馈，以及 RTF/显存/帧率。当前录制器为 960×540、5 fps 实时编码；即便模型变好，也应先实测能否提升到 720p 和更流畅的帧率，不能直接强开 1080p/60 fps 拖慢全链路。

推荐顺序：**冻结分项录像清单 → 轻量视觉升级 → 感知与性能短测 → 按行为逐段录制 → 带真实原因和残余说明剪辑**。阿克曼大圈问题仍需修正，当前短片可选已有合适曲率的短路径，但不能把避开该镜头说成已解决条带规划问题。

当前判断允许进入视觉升级和分项短测准备；尚未执行视觉资产替换或新录像。进入每个行为的正式录制，以该行为短测实际结果为准，不以文档中的“可以安排”代替实测。

## 2026-11-14 补充授权

用户允许本轮推进独立的 S18 交付内容，并将人工验证留给本人。前置核查仍是 S01–S16 PASS、S17 PARTIAL；未齐备的全地图与正式矩阵条件不能写成通过。S18 部分交付可先完成，最终状态以新回执为准。

跟随接口核查：`/s09/objects` 提供 odom 坐标下的位置、速度、尺寸、ID、观测年龄与确认状态；现有 MeasuredController 支持转发 `setSpeedLimit`。拟加入路径走廊内的同向目标筛选和间距/相对速度反馈。安全间距按车体与障碍外包络净空计算，包含反应和制动余量。跟随限速不得超过现有任务/定位/感知限制，不新增底盘命令出口。首次演示采用关刀连接路。

Nav2 Jazzy 的限速值 0 表示解除限速，不能作为停车命令；停车应走原动作与安全闸门，跟随输入过期也必须停止。低速控制、停走滞回、目标切换和原进度检查的配合都需要测试。[Nav2 Jazzy 官方限速说明](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/costmap_2d/costmap_filters/speed_filter/)
