# S10 技术原理：抽象动作与有效作业账本

本步把“机器人到达作业位置”和“工具真正完成工作”分开。任务层只调用统一 Action，工具适配层处理准入、启动、反馈、关闭；账本只保存观测确认的有效量。没有安装或搭建机械臂、MoveIt、VLA，也不把 Gazebo 电机转动等同于真实植物喷洒或割草效果。

## 系统中的四种信息

1. **请求**：POINT_SERVICE、START_WORK、STOP_WORK，包含地图/坐标 epoch/计划/工具版本、目标与幂等键。受理只是开始办理，不能直接计完成。
2. **观测**：Gazebo 插件给虚拟转子关节施加速度命令，再读取关节实际速度，产生延迟 0.02 s 的传感器观测；在线适配增加量化和微小转速噪声。喷洒流量根据仿真阀门及实际转速产生，关闭阀门立即停止流量；割草转子有停转尾迹。
3. **确认量**：在线定位 + 实测速度 + 工具反馈在时间和版本一致时才计量。无真值位姿输入，不用计划轨迹填补未观测路段。
4. **物理评分**：独立 domain 120 读取实际工具位姿/关节状态，离线与账本对比。显示账本少记的启动/停车尾迹及可能的超记，不能为让账本好看而对齐或回填在线坐标。

ROS domain 119 是在线系统，121 是原始仿真传感器，120 是独立评分。沿用 S04–S09 定位/感知分支；S10 准入直接读取 S09 地形健康和 0.45 s 新鲜度，并用在线估计的完整车体包络核查 S02/S09 已授权边界；短直线诊断驱动再受 S05/S08 及前向实测激光限制。完整 Nav2 风险层仍运行供观察，S10 不把大栅格转发回调的排队时刻当成工具感知时效，也不声称已完成 S13 闭环避障；工具唯一命令发布者为 `s10_tool_action_server`，车辆速度仍由 S03 唯一出口处理。

## 动作与联锁

C++ 服务端使用单线程 executor、定时状态机和异步账本 service。不会为每个 goal 启动无界线程；同一时刻只有一个工作 goal，STOP_WORK 可以抢占关闭。状态沿 `RESERVING → ADMISSION → WORKING → STOPPING → FINISHING` 演进。任何 ON 都要先完成账本预留及实际停转确认。

喷洒：工具中心到目标 ≤0.08 m，实际线速度 ≤0.01 m/s、角速度 ≤0.02 rad/s，定位准入、感知与目标条件有效。默认请求 2 剂量秒。有效流量是相对额定流量的无量纲数，不能当作升。S03 作用半径 0.20 m 保留。当前近景目标条件是标明来源的诊断预设；未来近景相机项目替换这部分。

割草：`COVERAGE` 且 segment_id 匹配，实测速度 0.02–0.12 m/s、角速度 ≤0.097 rad/s。条带完成阈值 95%，余下几何仍保存。TRANSIT/TURN 不积累作业。当前直线驱动是有安全门限的诊断运动，不是 S13 路径跟踪器或闭环避障演示。

感知短时失效（割草中也包括停车/重新加速时不在许可速度内）进入 `HOLDING`：工具 OFF，车辆停，账本暂停计量；确认停转且观测恢复后再准入。不把时限当完成，不把“已发送 OFF”当停转。定位失效、目标失效、喷洒速度不合法、硬件故障仍直接结束本次尝试并给出原因。正常取消可以有部分已确认量，仍返回 ROS CANCELLED，而不是伪报成功。

沿用原实测反馈思想：工作转速至少 8 rad/s 并连续确认 0.2 s；停止转速 ≤0.1 rad/s 连续确认 0.2 s。反馈最多老 0.1 仿真秒/0.5 现实秒，配对姿态误差 ≤0.04 s，反馈间隙上限 0.1 s。工具插件的命令超时为 0.2 仿真秒/0.35 现实秒。独立现实时钟监测防止暂停时 ON 一直保持。数值比较只允许 1e-6 s 浮点舍入误差，不放宽安全时限。

## 反馈驱动计量

喷洒按连续有效观测积分：`Δq = min(flow[k-1], flow[k], 1) × Δt`。低转速、失联、配对失败、准入无效或首次观测不能直接累积。启动确认窗口、丢帧和停机尾迹可能有物理作用但不记账，独立报告会公开差额。当前没有标定液体沉积、喷头压力与剂量均匀性，因此不能声称精准施药质量已验证。

割草足迹为实际估计工具中心、朝向下的 0.70 ×0.90 m 矩形，使用工程误差余量内缩后与目标多边形相交：

`F_k = snap_0.005(erode(tool_rectangle, 0.06 + hypot(0.35,0.45)×0.025 + 0.005) ∩ erode(target_area, 0.005))`

`C_k = union_0.005(C_(k-1), F_k)`；`R_k = target_area − C_k`。

Shapely/GEOS 执行并集、相交与差集。重复足迹不会重复加面积；没有跨丢帧间隔的路径插值。内缩余量是本次诊断的工程预算，不是来自 S08 协方差的置信证明，也不代表完整区域绝对定位精度达标。短时姿态跳变/定位失效由上游监督及配对门限拒绝；连接路/B 区已有地图形变问题仍需后续解决。

## 幂等、事务与恢复

SQLite 单写入节点使用 WAL、synchronous=FULL、BEGIN IMMEDIATE。一次事务同时插入观测 ID（epoch/seq/attempt 唯一）并更新量与几何。若写入失败，二者一起回滚，不能出现已加量但事件未记录的重复计账窗口。

同键、同 payload、已完成：返回旧结果，`replayed=true`，不启动工具。相同键配不同任务、目标或版本：拒绝。已关闭且部分完成：保存确认量，可以用原键继续。割草重叠取并集，不重复累计面积；几何重叠不等于转子完全不会再次扫过边缘，必要重叠与重复执行已完成任务是不同情况。

失联或运行中重启：数据库中的 RUNNING 转 RECOVERY_REQUIRED，并保留确认量和不确定标记。未确认的实际喷洒不能推断为未发生，因此不提供盲目重试按钮。需要后续任务管理器/人工复核确定新计划。数据库可以证明确认量“至多计一次”，不能证明断电瞬间物理世界的 exactly-once。

## 选择这些方法的原因与边界

| 方法 | 适合本项目的原因 | 代价与限制 |
|---|---|---|
| ROS 2 Action | 长任务反馈、取消和结果语义清楚；两类工具统一调用 | 幂等与恢复不是 Action 自动提供，必须另做 |
| 确认反馈状态机 | 故障原因可解释，能接实体工具反馈 | 比“命令已发即成功”更保守，可能有未确认物理作用 |
| SQLite WAL 单写入 | 便于事务、审计和进程重启；不必引入数据库服务 | 不是多机器分布式事务；存储可靠性需要硬件支持 |
| 几何并集账本 | 可画出已作业区域和剩余区域；重复路径不重复面积 | 多边形长任务可能变大，后续大地图应按簇压缩/栅格化 |
| 轻量物理转子 + 虚拟流量 | 验证启动/停止、延迟和故障，比直接回复成功更接近执行过程 | 没有真实液体、草体与机械臂接触动力学 |

诊断客户端在在线位姿稳定后才记录目标（最近约 3 s 观测中位数，仅用于选定演示目标；计量仍使用原始估计与工具时戳配对）。这避免把刚完成重定位的一帧瞬时偏移永久当成喷洒目标，没有放宽 0.08 m 到位门限。真实点喷洒任务仍需要导航到固定计划目标，不能靠移动目标替代到位。若启动阶段尚无可信定位，最多重复两次相同的已声明粗先验，且只在无任务、工具停转时进行；仍须通过传感器配准，不能强行放行。

关闭会话先停止任务客户端，再发 STOP_WORK，防止收尾时客户端发出下一个作业。即使关闭发生在数据库预留尚未返回时，C++ 服务仍会等待预留回应并完成关闭/终态事务。组件测试使用 SIGSTOP 暂停本会话账本进程制造该竞争条件，随后恢复；同时验证第二个工作 goal 被互斥拒绝。

## 异步消息与仿真时钟的顺序

消息传输到达顺序不等于观测时间顺序。复验发现，最新 Pose 可能先于同一时刻 `/clock` 的订阅回调到达；若无条件拿列表末尾 Pose 与较旧的本地 clock 比较，会把未来几毫秒的观测判成 CONTEXT_STALE。

修正采用事件时间配对：在线适配先缓存 Pose，等权威 `/clock` 到达该观测时刻才输出上下文；定位状态、地形健康、轮速各自从时间历史中选择不晚于该 Pose 的最近样本。账本发布准入状态时也只选择不晚于自身 `/clock` 的上下文。没有用数据消息推进时钟，没有扩大新鲜度门限，没有用仿真真值补位姿。生产账本回归新增覆盖“未来上下文先到达”的用例。

## 几何账本的实时性

实测暴露了另一个工程问题：浮点多边形并集产生细碎顶点，完整几何在每次观测、每次状态发布时反复构造与序列化，导致账本订阅队列滞后。修正后，高频控制状态只查询并发布标量；完整覆盖/残余几何仅在结果、查询与离线报告中生成。几何并集采用 0.005 m 固定精度，足迹和目标先额外内缩一个精度格，再对齐网格，抵消取整的外扩可能。仍只合并观测足迹，不跨缺帧补路径。

该方法使用 [Shapely 2.1.2 的 union 精度网格](https://shapely.readthedocs.io/en/2.1.2/reference/shapely.union.html)与 [set_precision](https://shapely.readthedocs.io/en/2.1.2/reference/shapely.set_precision.html)。新增 300 次微小位姿抖动测试，检查几何数据量有界、确认面积不因重复/数值细碎区域无限增长。固定精度是计算精度选择，不宣称传感器具备毫米级定位精度。

会话关闭复用已发现服务器的 Action 客户端发送 STOP_WORK；不依赖新建 CLI 客户端及时完成 DDS 发现。随后结束唯一工具命令进程，再等待 SLAM 保存/退出。若反馈无法确认，保留不确定状态；Gazebo 的独立命令看门狗仍会撤销 ON，评分器继续记录实际停转。

割草还需区分**启动许可**与**计量许可**。电机可在 COVERAGE 段、定位/感知有效且车速为零时启动；此时账本仍禁止加面积。诊断驱动等待实际转速达到工作门限并连续确认后才开始行驶；车速达到 0.02 m/s 后才允许计量。取消/等待后同样先恢复工具就绪、再恢复运动。这与原项目 STOP → START_TOOL → TRACK 的交接思想一致，避免机器人在转子启动过程中驶过条带起点，造成不可补记的漏割。

本轮普通喷洒任务的在线确认量约 2.048 剂量秒，独立评分的目标处物理作用量约 3.069 剂量秒。差额公开保留：本步的“成功”表示达到最低确认量，不代表对真实喷洒总量进行精密控制。重复启停、确认窗口和无效观测会造成保守少记；真实施药项目必须再实现标定流量与过量约束，不能直接把本步参数用于实体施药。
