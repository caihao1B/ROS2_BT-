# R10：停车后的定位重验与阿克曼换向控制

这轮修复保留原始 A1 的 56 个点、B1 的 34 个运动段、1800 仿真秒预算、原工作账本和验收门限。三任务单独运行，S17/S18 的正式矩阵仍未执行。具体运行结果以当前 `results/R10/latest.json` 和各次 `analysis` 为准；本说明描述实现，不把设计等同于通过。

## 定位突变不再只有“无限等待”这一条出路

在线定位仍以激光/视觉地图匹配与轮速 IMU 局部里程计组合，GNSS 独立核对位置。地图观测先经过原始跳变、GNSS 创新与新鲜度检查，再对 `map→odom` 修正做时间常数 0.8 秒的低通。不能先滤掉异常，再宣称观测合格。

当原 0.15 m / 0.035 rad 跳变门限触发，立即保留运动锁定。新增生产恢复协议有两个阶段：

1. 任务取消导航、停止工具并确认实际速度为零，发布带当前任务版本的 `RELOCALIZING` 状态。C++ 节点要求连续稳定观测、原 GNSS 一致性、原时间确认窗，以及仿真时间和墙钟均新鲜。只有停车重定位阶段允许评估最多 0.10 rad 的新方向修正；正常驾驶跳变门限仍为 0.035 rad，平移与 GNSS 门限不变，超界继续保持停车。
2. `prepare_revalidation` 生成新的定位 epoch，停车状态下安装候选变换，但仍保持运动锁定。仅规划和障碍代价层可以读取 `planning_valid` 预览。任务用原目标调用真实 Nav2 规划，验证完整车体在原先验内，并调用实时 `IsPathValid` 检查。路径哈希、地图版本、任务版本、epoch 和时间戳全部对应后，才调用 `commit_revalidation`。提交后还须经过原确认窗，才重新开放运动。

因此，恢复的依据是“停车后新观测可信，且原目标的新路径可执行”，而不是定时清除故障标志。恢复不会创造工作量，也不会把原义务改成当前位置。每个点的恢复尝试有界；不满足条件就停止并报告。

核心代码：`r10_backend/stopped_revalidation.inc` 实现 C++ 状态与两个服务；`mission_spray_r10.py` 编排取消、规划、检查与提交；`revalidation_spray_r10.py` 密集采样车体扫掠区域；`reference_spray_r10.py` 与 `risk_spray_r10.py` 将规划预览和运动许可分开。独立 ROS 域的 `probe_revalidation_r10.py` 调用实际 C++ 可执行文件，用合成输入验证拒绝和恢复条件，不将该测试算作真实作业完成。

拒绝记录包含观测采集时间、实际配对里程计时间、配对姿态、候选与旧 SE(3) 修正以及精确跳变量，避免再用不同时间的二维日志推断三维拒绝原因。

## 点喷速度参数必须匹配底盘出口

RPP 的曲率降速关系近似为 `v = desired_v / (radius_limit × |curvature|)`，故调节区间内 `|w| ≈ desired_v / radius_limit`。本轮短测曾把半径参数设为 0.45 m，使角速度约 0.47 rad/s，触发原 0.35 rad/s 的底盘限制，停止并报告无进展。随后改为 0.90 m，使调节区间约为 0.311 rad/s，并增加参数契约测试。

后续完整 A1 诊断又发现：即使名义曲率降速合格，0.03 m/s 的曲率最低速度仍可能在很小的目标误差下产生超限角速度，已实测到 60 次短暂命令拒绝。该诊断会话在完成 7/56 点后主动、有序停止，保留原分母及剩余任务，未宣称整簇通过。

当前候选把期望速度设为原上限内的 0.30 m/s，原地转向设为原上限内的 0.35 rad/s；0.90 m 曲率降速半径对应约 0.333 rad/s。曲率最低速度降至 0.005 m/s，直线接近最低速度仍为 0.03 m/s，接近降速距离 0.25 m。导航内部目标收紧至 1.25 cm，为停车后定位修正留余量；原 2.5 cm 导航准入与所有精停评分门限保持不变。

这组参数还有解析约束：当目标距离不小于 0.0125 m，且目标方位差小于触发原地转向的 0.45 rad 时，曲率上界为 `2 sin(0.45) / 0.0125`。乘 0.005 m/s 的曲率速度下限，角速度约 0.348 rad/s，仍低于原 0.35 rad/s 上限。更大方位差应先转向。配置测试同时检查名义曲率、最低速度与内部目标半径的匹配，实际闭环仍须通过仿真。

## 阿克曼恢复路径按前后挡拆分

原失败并非“规划器没有给出路径”：连续 Reeds–Shepp 已给出符合曲率约束的候选，但整条混合前后行路径交给控制器后，在换向点附近出现超调，实测曾离候选路径超过 4 m。

现在先用 Smac Hybrid-A* 搜索，必要时用原有 OMPL Reeds–Shepp 连续连接器补足末端几何。候选须保留原终点、完整车体边界、曲率、长度和实时障碍检查。随后按位移在车体朝向上的正负投影拆成单挡路径，每个换向点同时属于前后两段：

- 每段启动前确认车与工具停稳，并在唯一底盘出口预选方向。
- 单挡段由 Nav2 RPP 跟踪；关闭原地转向，保留碰撞检查。MPPI 配置仍保留供比较。
- 每次换向都结束当前 action，确认实际停车与换向点姿态，再启动下一段。
- 进度只在当前路径局部前缀推进，避免跳到空间上邻近的返程支路。距当前轨迹超过 0.25 m 时取消并停车，重新搜索仍受原 2 次 / 90 仿真秒预算约束。
- 原作业条带与原段终点未被替换；恢复只能在工具关闭的转场段使用。到达原终点后仍按原 0.10 m / 0.12 rad 段验收，覆盖量仅由真实工具反馈记账。

`recovery_mowing_r10.py` 实现拆挡、几何检查、局部游标和偏离距离；`mission_mowing_r10.py` 负责编排 Nav2 action、取消和实测停车；`control_mowing_r10.py` 保持唯一底盘出口和换挡互锁。RPP 的倒车与原地转向配置依据 [Nav2 Jazzy 官方说明](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/controller_plugins/configuring_regulated_pp/)。

## 通信桥正常收尾

一次短任务已完成全部工作与录像检查，但工具桥在 SIGINT 后触发底层互斥锁错误，退出码为 -6；该次会话仍记为未通过。新 `r10_backend/tool_bridge.cpp` 使用系统 `ros_gz_bridge::RosGzBridge` 及原消息转换、主题、方向和默认 QoS，SIGINT 只请求退出 executor；随后取消心跳、解除 Gazebo 反馈订阅并释放桥接对象，最后关闭 ROS 上下文。没有忽略异常退出码或重写成功状态。

这是针对本项目工具通道的生命周期封装，依据系统安装头文件及 [ros_gz 官方组件实现](https://github.com/gazebosim/ros_gz/blob/jazzy/ros_gz_bridge/src/ros_gz_bridge.cpp)。`R10 test bridge_shutdown` 在独立域连续六次验证双向原文消息传输，以及仍有消息发送时的正常退出；实际任务还须单独通过完整退出检查。原 R08/R09 运行器与通过证据不改。

## 持续检查位置，避免末端朝向状态锁住重新对准

另一次复验中，车辆重新对准时几乎只有零线速度、微小角速度，当前位置仍距目标约 4.5 cm。检查已安装的 Jazzy RPP 参数与官方实现后发现：`PositionGoalChecker.stateful=false`，但 `RPP.stateful` 仍使用默认值。RPP 一旦记住曾进入 XY 容限，后续会持续进入终点朝向阶段，定位修正后可能不再纠正位置；点喷任务恰好不要求终点朝向。

现在显式设置 `RPP.stateful=false`，使其与位置检查器一致：估计位置重新离开原 2.5 cm 导航容限时继续纠正位置。原停稳后的中位距离 3.5 cm、最新距离 4.5 cm、P95 分散度 1.5 cm 均未改变。配置回归测试检查两个参数一致；实际收益由后续会话验证。见 [RPP 终点状态实现](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp) 与 [位置检查器实现](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_controller/plugins/position_goal_checker.cpp)。
