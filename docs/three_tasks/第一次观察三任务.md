# 第一次观察三项农田作业

先看点喷车在第二个点发生卡滞的片段。卡滞前已经喷出的量会留在账本里，恢复后只补剩余剂量。这一件事串起了三层逻辑。导航负责把车停到目标位置，行为树决定是否准许工作，工具反馈决定这一点最终记了多少量。看完这个案例，再看巡检车跟随前车、割草车在感知中断时关刀。Windows 可直接打开或下载视频。本机依赖与 Ubuntu 从零克隆的准备步骤另有独立入口。[三段实录及原片](../../media/closeout_20261119/README.md) · [环境、资产与构建](复现检查.md)

如果手边只有 Windows，先把[离线任务回放](../../validation/closeout_20261119/replay.html)下载为 HTML，再用较新的 Edge 或 Chrome 双击打开。在 GitHub 文件预览页选择 **Download raw file** 可以得到原文件。回放包含数据、时间轴和代码，无需 ROS 或 Web 服务。文件模式在 Linux Chrome 上实测通过；本次没有进行原生 Windows 测试。下载并解压仓库后，打开[带事件跳转的视频播放器](../../media/closeout_20261119/index.html)，可在同一页播放同目录及仓库相邻目录的真实 MP4，请保留解压后的相对目录。选择本轮整簇案例时，可以逐个对照 [A1 点喷整簇原片（22/56 点）](../../media/closeout_20261119/spray_20261119_081218_417252_A1_partial_full.mp4)、[B1 割草整簇原片（25/47 段）](../../media/closeout_20261119/mowing_20261119_072044_764057_B1_partial_full.mp4) 和[点喷工时表](A1点喷工时校准.md)。

## 一、用同一次任务的证据回答三个问题

| 想弄明白的问题 | 在实时 GUI 里查看 | 查看结束后的证据 |
|---|---|---|
| **车为什么停了？** | 在“决策与执行”找动作、原因码和事件时间。再看“传感器与定位”的同一仿真时刻，判断是正在等定位、感知过期、跟车保持距离，还是导航阻塞。 | `decisions.jsonl` 中的 `action`、`reason_code` 和 `mission_events.jsonl` 的事件时间。同一次任务可能先有取消，再有停车确认。 |
| **它真的停住并关闭工具了吗？** | 看底盘实际运动、停车门控和工具状态。割草启动中断的短例可以同时看到取消与两项停车反馈。 | 作业任务的 `mission_result.json`、控制门控以及 `recording_acceptance.json` 中的物理检查项。巡检车没有机具，观察车距、轨迹和停车。 |
| **多少工作可计入结果？** | 点喷看目标编号、工具动作和账本，巡检看所选路线，割草分别看已行驶段、确认面积、原作业目标与残余。 | 点喷、巡检、割草分别读取 `analysis_spray_r10.json`、`analysis_r08.json`、`analysis_mowing_r10.json`。最后看视频时间线和图像新鲜度对应哪一个运行目录。 |

短例中点喷选择 3 个原始点，割草启动故障例选择前 5 个执行段。持续封堵专项允许以 `HUMAN_REQUIRED` 结束，合格依据是有限次查询后停车并上报。在正常整簇任务中出现同一终态，则要报告尚未完成的点或面积。[实时 GUI 手册](../../optimization_v2/three_tasks/monitor/README.md) · [各类任务的验收范围](收尾复验_20261119.md)

还有一个可以单独学习的现场选择。设备箱占据四个候选点中的第二个点，三次导航尝试均未成功；仿真第 80.944 秒，行为树发出第 14 号延后指令。机器人保留该点全部 3.0 单位的剩余剂量，转而确认后两个点，最终为 3/4。这个结果验证全局接近阶段的延后；末端精停耗尽的行为需另看相应证据。该试验独立于正式 A1 的 22/56。可用 [47 秒节选](../../media/closeout_20261119/spray_defer_highlight.mp4)、[347 秒完整原片](../../media/closeout_20261119/spray_defer_full.mp4) 和[帧时间与工具反馈](../../validation/closeout_20261119/spray_defer_media.json) 对照查看。

同样四个点在自然场景中走出了另一条实际事件链。原整簇曾中断的 10_20 经局部修正、停车重定位、原路径验证和再次精停，最终收到工具成功反馈。9_20 的两次取消在同一作业键下累计确认 0.590 单位，余 2.410 单位，整例仍为 3/4。独立物理评分器用 20 Hz 相邻样本的流量下界积分，在该点计得约 0.955 单位；作业账本另外要求位置和反馈合格，两个量须分开阅读。[31.6 秒重定位节选](../../media/closeout_20261119/spray_natural_relocalization.mp4) · [402.2 秒自然场景原片](../../media/closeout_20261119/spray_natural_full.mp4) · [工具反馈、帧时标与评分](../../validation/closeout_20261119/spray_natural_media.json) · [9_20 剂量逐笔复核](../../validation/closeout_20261119/spray_natural/point_9_20_dose_audit.json)

当最后一个点受阻，车已没有其他点可选。首次试验中，行为树虽然锁存人工处置，独立监听器收到的操作员通知却为零。修复后再次选取原簇中的两个点，首点确认，末点保留全部 3.0 单位。68.676 秒行为树要求人工介入，68.688 秒车体与工具均已停车，监听器实际收到请求及关闭两条消息。**人工交接通过，本次作业完成 1/2。** 可以在录像和 ROS 监听回执里分别验证这两个判断。[27.4 秒停车上报节选](../../media/closeout_20261119/spray_last_blocked_handoff.mp4) · [141.6 秒完整原片](../../media/closeout_20261119/spray_last_blocked_full.mp4) · [ROS 双通知与持久化交接核对](../../validation/closeout_20261119/spray_last_blocked/operator_attention_receipt.json) · [初版超时对照](../../validation/closeout_20261119/spray_last_blocked_initial_media.json)

## 二、在已验收的 Linux 主机上亲手观察

在终端一进入工程并打开 GUI。每个新终端都需切换到项目根目录。脚本会载入这套项目的 ROS 环境。浏览器打开 `http://127.0.0.1:8088`，首次选择“自动跟随”。

```bash
cd /home/ceihao/robot_project
bash optimization_v2/three_tasks/gui.sh
```

终端二单独启动一个案例。第一次建议运行点喷卡滞例。表中的时间是仿真时钟上限，现实用时随电脑负载变化。

```bash
cd /home/ceihao/robot_project
bash optimization_v2/three_tasks/advance.sh R12 record spray
```

| 观察目标 | 在工程根目录运行的命令 | 本案例的范围 |
|---|---|---|
| 工具卡滞、剩余剂量、重试 | `bash optimization_v2/three_tasks/advance.sh R12 record spray` | 3 个点，最多 300 仿真秒 |
| 保持车距、停车再跟随 | `bash optimization_v2/three_tasks/advance.sh R12 record inspection_leader` | 请求约 20 m 的跟随试验路段，最多 150 仿真秒 |
| 割草启动、取消、车停与刀停 | `bash optimization_v2/three_tasks/advance.sh R12 record mowing_startup_perception_loss` | 安全版前 5 段，最多 420 仿真秒 |
| 巡检原连接路 | `bash optimization_v2/three_tasks/advance.sh R12 record inspection` | 88.48 m 原道路，最多 480 仿真秒 |
| 在观测到障碍后绕行并回到原路 | `bash optimization_v2/three_tasks/advance.sh R08 test detour` | R08 绕行专项，默认 15 m、最多 240 仿真秒，生成独立分析记录 |
| 持续封堵，停车并请求人工 | `bash optimization_v2/three_tasks/advance.sh R12 record inspection_blocked` | 请求约 20 m 的路段，最多 120 仿真秒 |

## 三、读懂一个可追溯的结果

下面的只读命令适用于有原始录制目录的机器人主机。它列出最近的三个短案例、任务检查、录像时间线、任务用时与证据目录。把输出里的目录名与 GUI 当前选中的运行名对上，便能避免把上一轮录像与本次停车混为一谈。

```bash
cd /home/ceihao/robot_project
python3 - <<'PY'
import json
from pathlib import Path

results = Path("optimization_v2/three_tasks/results/R12")
for case in ("spray", "inspection_leader", "mowing_startup_perception_loss"):
    pointer = results / f"{case}_latest.json"
    if not pointer.is_file():
        print(case, "尚无本机录制回执")
        continue
    row = json.loads(pointer.read_text())
    print(case, "任务通过", row["task_passed"], "时间线完整", row["mission_timeline_complete"],
          "画面新鲜", row["active_video_quality"], "仿真秒", row["sim_seconds"])
    print("  运行目录", row["path"])
PY
```

`python3 -` 从终端输入读取程序，`<<'PY'` 到单独一行 `PY` 之间是完整的 Python 代码。`Path` 拼出相对项目根目录的文件路径，`json.loads` 把 JSON 读成可按键取值的字典。新克隆没有这些本地录制目录时，仍能从发布素材清单核对案例范围、回执摘要、片段时间和视频哈希。[发布素材与检查项](../../validation/closeout_20261119/media_manifest.json) · [整簇录像与结果](../../validation/closeout_20261119/media_full_runs.json)
