# R10 三任务分别验收

R10 不用局部组件测试替代完整簇。正常用例为完整 A1 原点序、完整 88.48 米连接路、完整 B1 原条带与地头序列；其余 A2/A3/B2/B3 以及六十次正式矩阵仍保留原任务与原状态。原 S17/S18 不因 R10 改为 PASS。

点喷完整任务采用 R08 修复后的共用定位和地形处理，生成独立 R10 任务版本后重测，原 R07 两个三点通过回执不改。巡迹与割草已通过的同版本受阻用例可以引用封存的原始证据；聚合时重新检查所有源码绑定、数据哈希、真实停车和残余，不仅引用一张 PASS 截图。

受阻案例包括工具真实 JAM 与残余重试、前车停止/恢复、实时观测绕行、持续阻塞后的有限规划与人工报告。它们的 PASS 含义分别明确：受阻后确认停止与留下未完成义务，不能等同于工作完成。正常全簇未完成时整体保持 PARTIAL，不用修改任务分母或降低覆盖标准掩盖。

覆盖账本与路线账本分开：所有条带段实际到达也可能有受误差侵蚀、地形、速度或工具反馈限制的未确认面积。报告同时列出选择范围、原始分母、确认量、残余、停止原因、仿真秒和墙钟秒。

R10 点喷单独使用 R09 已验证的 50 Hz 物理电机反馈插件、工具独立桥接与原始时间戳缓冲。喷量、停止速度、反馈有效期与故障恢复判据不变；它仍需本阶段真实点喷与卡滞测试，不能由割草用例推定通过。

## 地头执行方式的实际对照

首次完整 B1 运行在短倒车弧线末端因无进展安全停止。R09 将曲率变化点都设成停车目标，叠加一次临近终点的恢复后，仅剩极短的两点路径；RPP 的末端切线不再可靠，而阿克曼车不能原地补航向。这项完整运行失败保留。

R10 曾测试独立割草任务版本，把几何连续、同挡位、工具关闭的相邻地头段合并成一次 FollowPath；换挡、工具状态变化和真正不连续处仍分别停车。原始每一个路径点、工作区域和 34 段分母保持不变。中间段末端必须按顺序被合格定位实际观测到，位置误差不超过原 0.10 米、航向误差不超过原 0.12 弧度；只有通过记录齐全的执行组才确认对应原始段。连续执行组最终目标仍使用原 Nav2 0.05 米/0.08 弧度到达条件及物理停车检查。

恢复时保留原路径末端切线，不再把当前车位和终点临时连成一条新的两点短线。转场全程工具必须物理停止，原工作条带各自使用原账本目标区域和幂等键。该改动只属于 R10，不重写 R09 的已封存五段测试。

连续执行的完整测试还发现一个调度边界：执行组已经成功到达后仍检查重试失败上限。现改为成功先终止，只有尚未完成时才评估次数；每个原始段仍最多六次，合并组按原始成员数保留对应总预算。仿真总时限、无进展监督、有界规划查询和安全停止门限不变。分组组件检查包含“成功不能被失败计数反向覆盖”和“合并不改变原始义务预算”。

## 作业与地头采用不同的控制参数

完整复验显示，同一组地头在不同观测误差下，末端仍可能超过原 0.08 弧度 Nav2 航向条件；RPP 要求反向修正时，会被当前挡位约束正确阻止。连续分组试验曾为关闭工具的地头段选择独立 `TurnRPP`：速度 0.12 m/s、固定曲率预瞄 0.35 米；条带仍使用 0.35 m/s、0.8 米预瞄。两者都是真实 Nav2 RPP 插件，由同一个控制服务选择，经过同一个底盘门控出口。短转场降低速度，为实际转向关节建立角度留出时间；短预瞄减少短弧末端切线外推的影响。没有降低原终点、曲率、障碍、定位或停车门限，完整 B1 仍受 1800 秒仿真总时限约束。

点喷与割草分别绑定实际使用的任务脚本、各自生成配置和共用已封存依赖，避免修改未被点喷导入的割草代码就使点喷证据无效。共用文件或本任务输入变化仍必须重测，最终 R10 回执另行封存总调度与报告源码。

## 当前默认：按原始运动基元停车

连续分组复验出现短弧检查点位置约 0.019 米、朝向约 0.179 弧度的偏差，超过原 0.12 弧度检查条件；该失败保留。当前默认恢复为 `original_primitive_boundaries`：34 个原始段各自作为原生 FollowPath 目标，曲率或挡位变化处均确认停车。原始路径点和工作区域不变，不能以到达后面的点跳过前面的姿态义务。

正常工作与关刀段均采用 R09 已验证的固定 0.8 米曲率预瞄、0.35 m/s 期望 RPP；倒车仍受出口 0.25 m/s 上限约束。保留原路径末端切线、成功优先的重试判断和新增换挡互锁；若短段末端确实停滞，才进入下述独立有界恢复。分组算法保留作对照工具，默认任务不再启用。

## 同栅格末端的有界姿态恢复

不能靠放宽 0.05 米 / 0.08 弧度目标条件来掩盖阿克曼车的末端偏角。此前的原始检查点已按序经过、合格定位距离当前段最终点不足 0.25 米、连续 3 秒没有至少 0.01 米接近进展且 BT 仍允许执行时，先取消当前 FollowPath，确认车体和刀具停止，再生成恢复候选。已经锁定人工处理的 BT 不会被自动清除。

真实 Smac Hybrid（Reeds–Shepp）先查询原终点。本次极短端点修正曾返回单点或带离散曲率跳变的候选，这些均被拒绝。若直接候选不满足条件，则复用 R03 的原生 OMPL Reeds–Shepp 求解器，从当前合格定位连接同一个原始终点，输出带正负长度的圆弧/直线基元。候选以 0.04 米间距精确积分，半径使用物理最小半径加 0.10 米。

OMPL 只解决无障碍条件下的运动学连接，不能自行证明场地可通行。新候选必须依次通过原先验内整车扫掠轮廓、曲率/长度/端点检查，以及 Nav2 `is_path_valid` 对当前全局代价图的整车轮廓检查；执行期间仍受实时局部感知门控。每次恢复最多两个候选和 90 秒仿真预算；Smac 查询与连续求解分别计数。失败即保留残余并上报，不能宣称已经证明全局无路。

依据：[OMPL Reeds–Shepp 状态空间](https://ompl.kavrakilab.org/core/classompl_1_1base_1_1ReedsSheppStateSpace.html)、[Nav2 Jazzy 整车轮廓代价检查](https://docs.nav2.org/jazzy/configuration_and_development/configuration_guide/core_servers/costmap_2d/)。
候选由 Nav2 MPPI 的 Ackermann 运动模型执行，工具始终关闭。MPPI 在短时域采样速度序列，通过障碍、路径、目标位置和朝向代价选取控制量；最小转弯半径使用车辆真实曲率约束。换挡请求先被唯一底盘出口拦下，只有测得停车且刀具关闭才允许换向。最多两个候选、90 秒仿真恢复预算，不修改整体 1800 秒预算。原 RPP 用于正常工作条带和逐基元地头。

官方依据：[Nav2 Jazzy MPPI 参数与 Ackermann 模型](https://ros-navigation.github.io/mkdocs.nav2.org/jazzy/configuration_and_development/configuration_guide/controller_plugins/mppi_controller/configuring_mppic/)。这里使用可行路径朝向模式 `PathAngleCritic.mode=2` 和路径换向点处理，实际成效必须看本轮仿真回执，不能由控制器名称推定。

## 点喷停靠与曲率限速

当前点喷版本使用期望 0.28 m/s、任务上限 0.30 m/s；RPP 的曲率减速半径为 1.4 米，原地对向速度 0.25 rad/s，任务角速度上限 0.35 rad/s。用曲率减速使控制器自然产生符合出口范围的命令，而不是抬高原安全拒绝阈值。DWB 参数仍保留，但当前点导航 XML 选择的是 RPP。

导航位置到达条件由 0.05 米收紧到 0.025 米。工具原停靠误差 0.08 米不变。停车后额外检查至少 1.8 秒、20 个有效观测，要求中位距离 ≤0.035 米、最新距离 ≤0.045 米、相对中位位置的 P95 抖动 ≤0.015 米、观测间隔 ≤0.15 秒。每次稳定检查最多 8 秒，失败进入有界重新停靠；工具故障、漂移导致的部分剂量仍由同一幂等键补作，未确认量不会被伪造为完成。

`κ=2y/L²` 是 RPP 的基本跟踪关系，弯道线速度随曲率减小，因而 `ω=vκ` 也保持可执行。MPPI 在恢复时评价采样控制序列的障碍、路径和目标代价；候选组合使用代价指数权重得到更新，再通过唯一出口的速度、曲率和换挡互锁。两种方法都以实际状态和真实碰撞代价为输入。

点喷与割草的源码和配置分别绑定；改变一个任务的内部算法不自动使另一任务的已完成证据失效。共同定位与物理工具依赖变化仍要求重新复验。

普通段之间的顺序为：取消导航和工具动作 → 实测车体与刀具停止 → 在 READY 阶段选择下一段挡位 → 出口确认 → 启动工具（工作段） → 发送 FollowPath。恢复中的换向仍在关刀状态执行，未停车时出口强制零速。此顺序解决倒车转前进时工具先启动与换挡互锁之间的冲突。

## 近目标无距离进展的提前重规划

完整 A1 耗时诊断中，第 4 点第一次导航达到 120 秒上限；从当时实测位置重新规划后约 12.2 秒到达，随后补充停靠通过并完成剂量。这表明只有总动作超时不足以迅速处理末端徘徊。该诊断有序终止，保留实际完成量，不算完整簇通过。

当前独立点喷版本在目标 0.25 米内统计合格定位：连续 8 秒没有至少 0.005 米距离改善、窗口内平移命令累计至少 2 秒、至少 20 个样本且最大间隔不超过 0.15 秒，才取消当前导航并进入原 BT 有界重规划。只原地对向不触发；定位失效、样本断流或离开近目标范围则清除证据。原 120 秒单次上限、最多三次导航尝试、1800 秒总预算以及全部停靠/工具门限不变。

恢复仍使用真实 NavigateToPose/Smac/RPP 和实测停车，不能由 Python 直接移动机器人。重新生成点喷任务版本并复验真实 JAM 与完整 A1；旧三点录像保留为旧版本证据，不继承为新版本通过。[RPP Jazzy 原生实现](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_regulated_pure_pursuit_controller/src/regulated_pure_pursuit_controller.cpp) 的曲率跟踪和转向逻辑保留，本次改动属于任务层的进展监视与有界路径刷新。

## 恢复中的短时观测中断

`mowing_20261114_172924_433566` 的两次真实恢复候选均通过整车先验和实时代价图检查，执行期间分别因约 0.5 秒和 0.3 秒的方向保护栅格观测而取消。旧实现把每次短暂停车计成一次候选失败，立即耗尽两次搜索；这不能解释为没有可行路径。该记录同时未通过录像新鲜度检查，保留失败结果。

当前实现将“新候选搜索”与“原候选暂停后恢复”分开：每次仍取消动作、确认车体/刀具停止，等待带新时间戳的 BT 放行，然后重新检查剩余路径的首端连续性、原终点、曲率、整车扫掠轮廓和实时 `is_path_valid`。路径进度只沿前方 0.20 米弧长窗口推进，防止近距离折返曲线误匹配到后面的支路；任何偏离准入范围都会拒绝续行。最多两次候选、总计六次观测恢复、原 90 秒总预算均有界；人工锁定不可自动清除，不删除短暂障碍栅格或降低停车门限。

Nav2 自身也会在换向点前裁剪路径，并依据位置/方向容差推进下一部分，见 [Jazzy PathHandler 实现](https://github.com/ros-navigation/navigation2/blob/jazzy/nav2_mppi_controller/src/path_handler.cpp)。任务层游标用于取消后重发同一候选，两层的职责不同。实际恢复成功仍须由新版本真实录像与终点记录确认。

当前完整 B1 运行 `mowing_20261114_174644_953306` 在第 7 个原始段记录了一次真实恢复成功：265.952 秒触发，314.22 秒实际段到达，位置误差 0.03542 米、航向误差 0.00685 弧度。首候选在感知中断后因首端不连续被拒绝续行，第二个连续候选经重新准入后由 MPPI 执行到达；没有绕过原终点检查或停车换挡。该事件证明本次恢复流程实际走通，不代表原候选无中断续行、所有地头姿态或完整 34 段都已通过；全簇结论看最终结果。
