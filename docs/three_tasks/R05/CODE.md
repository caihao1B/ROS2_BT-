# R05 核心代码与算法分工

源码目录：`optimization_v2/ws/src/task_platform/scripts/`。

- `rig_r05.py`：按车身配置生成传感器外参、自体过滤边界与版本绑定；在隔离目录生成适配脚本，通过唯一字符串断言检测上游源码变更。`compose()` 将真实传感器挂在物理车体上。
- `regional_r05.py`：时间对齐点云与局部里程计；冷启动多候选配准，跟踪时用局部里程计预测初值；调用原 S14 地图匹配数学代码，对未参与拟合的一半点独立复核；再以 GNSS 天线杆臂计算创新和 NIS。没有世界真值订阅。
- 原 `regional_math14.py`（生成新量程适配副本）：最近邻粗配准、平面法向约束、可观测性检查、留出点误差与重叠检查。方法适合有树干、墙面等结构的区域，不适合只有水平地面的长期绝对定位。
- 原生 C++ `rtabmap_odom/icp_odometry`：通过相邻观测估计局部运动；`robot_localization/ekf_node` 融合轮速、IMU 和通过检查的激光增量。新 Python 静止一致性检查拒绝与轮速/陀螺同时静止窗口矛盾的 ICP 运动；原始诊断仍保留。
- `observer_r05.py`：只用在线观测和里程计执行受限往返；等待当前地图匹配后才发送有版本、序号和租约的运动请求；使用上次观测位姿作为重启粗先验。
- `runtime_r05.py`：真实节点启动、就绪、定位进程重启、受控退出、原数据库不变检查；真值桥只在独立评估域。
- `analyze_r05.py`：事后对时间戳插值评估 XY/航向误差、真实运动距离、传感器和唯一 TF 发布者；不是在线定位算法。

本步新增 Python 适配与监督，复用已有原生 C++ 定位和物理底盘组件。没有为了展示而增加一个与运行路径无关的示例 C++ 算法。
