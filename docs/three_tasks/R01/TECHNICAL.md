# R01：三任务配置与生命周期

本阶段把点喷、巡迹、割草分成三个可独立启动、独立版本绑定、独立保存结果的任务。三者共享原地图、冻结 RTAB-Map 数据库、定位监督、安全门、工具接口和导航实现；运行时只允许一个仿真会话占用项目资源。这样可以单独复测一个任务，不必从点喷一路运行到割草。拆分本身不会使相同作业量自动变少。

## 配置与版本

三个 profile 位于 `optimization_v2/three_tasks/config/tasks`，分别选择任务操作、底盘、控制器和簇。R01 的点喷及巡迹继续使用已验收的轻量差速底盘，割草使用已验收的轻量阿克曼底盘。Husky、Jackal、Dino 的尺寸、碰撞体和参数调整属于 R02，尚未实施。

配置版本是去除 version 字段后，以排序 JSON、UTF-8 和固定分隔符得到的 SHA-256。配置同时绑定世界、地图、规划、工具、导航参数和兼容库锁文件。输入改变时拒绝启动，避免用新参数解释旧验收。`versions/<task>/<hash>.json` 是配置存档；实际运行再次保存配置和源码哈希。

## 共享算法、独立任务

|任务|R01 操作|导航与控制基线|工作范围|
|---|---|---|---|
|spray|原点服务簇|原导航到点链路 + DWB|A1/A2/A3，逐次指定|
|inspection|原连接路巡检|原巡检路径执行链路 + DWB|原连接路，A1 仅为启动锚点|
|mowing|原条带簇|原条带路径执行链路 + RPP|B1/B2/B3，逐次指定|

任务分离不等于三套新行为树已经实现。R01 通过原适配器选择已有操作，保持 S14 的解释事件和工具反馈；专用 BT 和专用规划分别放在 R07/R08/R09。新的通用启动器也没有启用未通过收益门槛的预测模型。

## 有界启动与退出

启动依次经过配置哈希、原地图/计划版本、Gazebo ABI/库哈希、共享文件锁检查，随后创建任务专属运行目录、ROS domain 和 Gazebo partition。相同机器只运行一个会话；第二次启动拒绝进入。

停止只能作用于指定任务的会话。PID、UID、Linux start_ticks 和命令行标识共同验证身份，避免 PID 重用时误杀其他程序。原任务链负责取消任务、发零速、关闭工具并确认 STOPPED、停止定位和其他节点，最后停止 Gazebo。最后的清理按本次记录的 partition 和创建时间收尾，不使用 killall。正常停止、失败、退出码及未完成作业均保存。

默认任务预算 300 仿真秒、720 现实秒；短测在 60 仿真秒提出停止请求，收尾仍计入实际时间。短测证明启动、准入和停车清理，不证明整个簇完成。`lifecycle_status`、`mission_status`、`formal_credit` 分开记录；R01 的所有短测 `formal_credit=false`。

## Gazebo 退出兼容修复

原完整项目相机场景可复现退出 -11。仅静态官方相机场景不能稳定复现，单独预加载 Boost 也不能修复完整场景。GDB 分别指向 Boost 线程局部存储回调的库生命周期，以及 Gazebo 停止事件列表的并发访问。

新入口仅向 Gazebo server 注入一个进程内兼容库：链接并保留 Boost thread，串行调用 Gazebo 8.15.0 的原始 `SimulationRunner::Stop()`。它继续调用真实停止函数，不跳过析构、不改写退出码，也不拦截传感器或车辆指令。ROS 进程不注入该库，系统安装和旧入口不修改。

这是一项针对当前已锁定二进制的兼容处理，不是已合并上游的通用修复。Gazebo、Boost 或兼容库更新后，哈希门禁要求重新检查和真实复验。仍需上游长期修复；旧入口的历史退出结果不被重写。

## 保留范围

阶段开始时按照 S01–S18 的原始回执，冻结 41,331 个文件的摘要，完成后逐文件复查。原地图、正式任务、覆盖率分母和历史状态不变。S17 与 S18 仍为 PARTIAL，R01 通过不提升这两个阶段。

## 默认可视化修正

原生成的 RViz 配置在 odom 固定坐标系中使用区域 map 坐标作为焦点，车辆会出现在画面之外。新入口只修改本次生成的相机视图：Target Frame=base_link，局部焦点归零，保持原 TF 和数据不变。RViz 跟随估计底盘坐标，显示感知/导航数据；此视角设置不参与控制。

RViz 收尾先按本次记录的 PID 查询窗口，再向窗口管理器发送关闭请求，使 Qt 正常退出；只读监视窗口不参与速度输出。原通用 SIGINT/超时清理作为后备，任何非零异常退出仍记录为失败，不把 -15 视为正常。

本机 RViz 14.1.24 的 ImageDisplay 析构在 `message_filters::Signal1<Image>::removeCallback` 处崩溃，独立空数据窗口也能复现，诊断日志保留在 R01/rviz_gdb 目录。新默认视图移除这个显示插件，保留点云、代价、路径和车体轮廓。摄像头传感器、视觉识别与 `/s09/camera/annotated` 图像话题继续运行；这不是关闭视觉感知。图像面板恢复需要后续独立修复和复验。

窗口关闭前只向本次 PID 的窗口发送保存当前生成视图的快捷键，避免退出时保存对话框阻塞；不切换桌面焦点，不保存其他应用或原始配置。RViz Jazzy 的保存提示行为参见[上游 prepareToExit 源码](https://github.com/ros2/rviz/blob/jazzy/rviz_common/src/rviz_common/visualization_frame.cpp#L867)。
