# R06 共用可解释行为树与运动监督

本步建立三任务共用的实际 BehaviorTree.CPP 组件，后续 R07–R09 再接入每种任务。输入来自有时间和版本契约的任务上下文，输出结构化决策；本组件不发布底盘或工具控制，不能替代独立安全出口。

优先级从高到低是：立即安全停车、版本有效、上下文新鲜、定位与传感器准入、停车预算、人工锁定、反馈完成、障碍交互、任务执行。通过 ReactiveFallback 每次重新检查高优先级条件。障碍分支比较短暂等待、经过验证的局部绕路、持续阻挡后的有限次全局重规划、保留残余并切换义务，以及人工处理。它不是“规划失败后不断重复同一个命令”。

等待使用 3 秒短阻挡窗口和 1 秒清除迟滞；持续阻挡达到 12 秒可查询全局规划，最多 2 次重规划、3 次任务延期。45 秒阻挡上限用于不能跟随的情况。无法取得可行候选只能说明当前有界搜索失败，输出明确不宣称数学意义上全局无解；不强制完成 95%，不改变原任务分母。

同向跟随必须具备在路径上、同向、可信跟踪、移动目标、最小 2 米间距、至少 3 秒 TTC 和有效路径。速度上限为目标速度与间距误差校正后的较小值；这不是对任意移动障碍进行跟随。持续运动但 10 秒无至少 0.1 米观测进展触发锁定上报。交叉行人不能进入同向跟随分支。

切换导航动作之前必须先取消并等待导航空闲、底盘停止和工具停止三个反馈；超时进入停止与人工锁定。明确的停止命令立即发出取消和工具停止请求。人工锁定需要显式确认服务，且车辆和工具已停、观测新鲜、版本正确、定位可信、安全条件满足；障碍物刚消失不会自行解除。

每条输出包含原因码、支持该判断的输入、阈值、候选动作的可用性和拒绝原因、选择结果及分派序号。图和日志对应实际 BT 执行。R06 协议用例使用声明的合成上下文，通过真实 ROS 通信和 C++ BT 执行；不冒称已完成摄像头识别人、物理绕障或全任务。
