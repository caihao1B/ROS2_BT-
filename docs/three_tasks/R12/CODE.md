# R12 核心代码

`prepare_r12.py` 生成独立的三种运行器，并保存可审查的派生清单；`stage_r12.py::record` 检查源版本、运行原生任务、评分真实物理/动作数据，再验证录像时间线。`record_r12.py` 只订阅观察相机，读取当前任务与反馈账本，向 FFmpeg 写实际帧；不发布车辆、工具、定位或规划命令。

`export_r12.py` 校验原片和单调时间线，输出完整拼接与标注倍速的精简版，生成本地视频播放页。C++ 核心仍是 Gazebo 物理/渲染、Nav2、BT 和工具动作服务；录像代码不替代这些组件。

`highlights_r12.py` 根据实际工具故障/补作、绕行准入/接回和关刀换行事件选择原片区间；跟随片段要求独立停车/恢复/净距评估通过。`export_r12.py` 把仿真时刻映射到逐帧记录中的原片时刻，截取后明确标注倍速。不存在的行为不生成替代画面。

完整 A1 的行为片段优先选择同一目标的实际停车重定位请求到 `LOCALIZATION_REVALIDATED_RESUME`；只有请求而未恢复时不生成成功片段。若本次未发生定位恢复，则选择局部精停后、同一目标真正 `SUCCEEDED` 的工具反馈区间。幂等重放不算新的作业成功。

完整 B1 若没有实际覆盖接回事件，可选择同一段的末端停滞、实际恢复选挡和 `ENDPOINT_RECOVERY_SUCCESS` 区间。只有停车观测确认、未进行恢复运动的情况，不标成“运动恢复”；不同段的事件也不能拼成一次成功。

持续受阻片段额外要求真实 `HUMAN_REQUIRED` 终态、有限查询、实测停车和残余保留检查通过，才使用实际中断到上报的时间段。其说明是“本次有界搜索未获得可准入路线”，不是全局无路证明。

`declared_scope_matches` 将命令参数 `distance_limit`、`seconds` 显式映射到实际运行记录中的 `distance_limit_m`、`sim_seconds`。它同时核对任务、案例、点数/段数、距离范围与时间预算；完整连接路必须是零截断值，短距离交互案例不能替代它。4 项回归检查覆盖实际字段名、用局部替代完整路线、修改任务/预算、用五段替代完整 B1 的情况。


`prepare_mowing_video_r12.py`、`prepare_spray_video_r12.py` 生成独立观察图像传输版本；`transport_video_r12.py` 仅给 `video_bridge` 应用已有大图像缓冲。`runtime_binding_r10.py` 根据确定性派生内容验证点喷录像运行器，不以文件自己声称的哈希放行；修改运行器后同时更新其自报哈希仍被拒绝。控制、传感器融合和工具节点不使用新的观察图像配置。
