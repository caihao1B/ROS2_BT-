# R08 核心代码

源码在 `optimization_v2/ws/src/task_platform/scripts/`，R07 已封存代码保持不变。

- `prepare_r08.py`：组合 R03 原路线、R04 巡迹车、R05 外参与 R07 通行/导航基础；生成独立任务哈希、Nav2 配置和无工具契约。
- `scene_r08.py`：生成带实际传感器的 Jackal 尺寸参考物理车；动态夹具只给场景障碍物施加运动，不能读取或写入机器人定位。
- `startup_r08.py` / `regional_r08.py`：从实际地图修正历史检查初始稳定性，保留原观测配准和 GNSS 检查。稳定性只是原生监督之前的新增准入门，不拥有 map→odom TF。
- `tracker_r08.py`：实际 PCL 几何对象→关联跟踪→路径坐标投影→前车候选→测得自由空间包络。使用真实观测年龄与置信度，不读场景夹具。
- `control_r08.py`：唯一底盘请求出口；同时检查定位、地形、行为树、任务版本与时间新鲜度。FOLLOW 仅在合格前车和安全距离下限制速度，不能越过物理地形停车。
- `mission_r08.py`：实际 FollowPath 动作发送、取消确认、停车确认、剩余路径恢复、到达检查；规划器候选尚未通过当前观测绕行资格时明确上报未实现，不偷偷下发。
- `runtime_r08.py`：单任务会话锁、隔离 ROS 域、版本/源码绑定、真实节点生命周期和有序退出。
- `analyze_r08.py`：运行结束才读取真值，独立计算定位误差、横向误差、实际进展、接触、唯一出口及数据库不变；不参与在线运动。

实际 C++ 路径继续复用 Nav2 RPP/FollowPath、Smac、原生 GNSS 监督、R07 三维地形组件和 BehaviorTree.CPP 分层树。没有为说明文档另写一套不运行的 C++ 示意控制器。Python 负责任务编排、契约和观测适配；C++ 负责物理驱动、通行处理和实时导航/决策组件。

`path_envelope_r08.py` 区分当前实际物理轮廓的自身盲区与未来路径未知格；测得危险在任何位置都不会清除。`diagnostics_r08.py` 只订阅并保存近车体实际地形和 Nav2 代价格，用于复现观测空隙，不发布控制或定位消息。任务取消/失败后还必须等待时间戳晚于事件的新 BT 上下文，禁止读取旧 EXECUTE 导致无限重试。

当前车体清除不包含额外安全裕量；裕量中的未知地面仍需真实观测，不能因为机器人附近有盲区就扩大自由空间。
