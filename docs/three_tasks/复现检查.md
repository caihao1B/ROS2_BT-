# 从 GitHub 恢复三任务地图并检查路线

在 Ubuntu 24.04 的新克隆中，可以独立恢复冻结地图、核对三台车的传感器与地图绑定，重新检查六簇和连接路的离线路径。本页同时给出开发机的运行前检查。所有 doctor 命令只读，退出码 0 表示所选检查通过，退出码 2 表示有缺项。执行时不会启动 Gazebo 或更新阶段回执。

## 一、恢复原始输入

首次使用在空目录执行以下命令。已有此仓库时从仓库根目录执行第三行。

```bash
git clone https://github.com/caihao1B/ROS2_BT-.git
cd ROS2_BT-
python3 scripts/restore_assets.py
python3 scripts/restore_assets.py --manifest assets_bundle/three_tasks_r01/manifest.json
python3 optimization_v2/three_tasks/doctor.py assets
```

恢复脚本从 `assets_bundle/` 的 90 个已发布分片还原 27 个文件，先检查归档、分片和逐文件哈希。冻结数据库为 150085632 字节，SHA-256 为 `b4d1a2d508ad9dc17205f77ba34ffb8a8e662e2f0f27a8f94119e7147df4bb82`。它已经包含在分片中。早期 R12 文档中关于这个文件必须从开发机另外迁移的说法，已由实际克隆与还原结果更正。

第二次恢复命令读取独立的 R01 历史索引压缩包。其内容是 41,331 个相对文件名及哈希、18 个阶段状态与回执哈希，原始运行数据需要单独保存。三份 R01 车辆配置固定了这个索引的原始 SHA-256。连续执行两次恢复会得到相同的内容。

三车传感器绑定还引用了后续生成的区域图集。新补入的 14 个文件包含 C 区点云与占据栅格、S17 原图集与原任务计划、R03 的三任务路线和两份分区文件。这些文件采用验收时的原始字节。A/B 区的五类地图文件各自在原仓库中。doctor 调用定位节点使用的三套 R05 契约，核对 10 个冻结地图文件，再核对区域图集、原始任务计划及三份执行配置的关联。这里的 `passed` 仅描述所检查的输入。

## 二、重算作业区与路线的几何检查

使用 Ubuntu 系统 Python 的独立虚拟环境。系统包依赖及完整构建方式见仓库根目录 `BUILDING.md`。以下命令假定已装 `python3-venv`、`python3-numpy`、`python3-yaml`。录制依赖 `imageio-ffmpeg` 与几何库一起固定版本，便于稍后使用相同环境。

```bash
python3 -m venv --system-site-packages optimization_v2/venvs/scene
optimization_v2/venvs/scene/bin/python -m pip install 'shapely==2.1.2' 'imageio-ffmpeg==0.8.1'
optimization_v2/venvs/scene/bin/python optimization_v2/three_tasks/doctor.py plans
```

命令直接调用项目的 R03 路线检查器，逐项计算 A1–A3、B1–B3 和 road 的连续性、车身轮廓、转弯曲率及作业动作条件，同时核查两区各有三个连通簇。它随后调用 B1 安全执行路线的几何检查器，检查原目标多边形、整车包络、换挡点及时间预算。当前计划应报告 17 个通过的 R03 几何检查，B1 有 47 个安全执行段、原参考路径 34 段、原作业目标并集约 188.39 m²。路段数和预计工时都是计划量。实际完成量由任务日志和工具反馈账本给出。

### 未开仿真时，B1 的刀盘名义上能扫到哪里

```bash
optimization_v2/venvs/scene/bin/python optimization_v2/three_tasks/mowing_area.py
```

原 34 段路线的开刀条带对应 188.3918 m² 作业目标并集，占 195.9944 m² 原簇的 96.12%。新的 47 段执行路线包含 10 个开刀片段和 37 个关刀连接段。按平面理想跟踪、0.70 × 1.60 m 有效刀盘和 0.819 m 前向安装位置，逐条与各自原作业键的目标多边形相交，再求并集，得到 **112.7887 m²**，占原作业目标 **59.87%**，占整个原簇 **57.55%**。有 75.6031 m² 原作业目标没有被名义轨迹扫到。完整通过全部路径段，因此也不能直接换算为覆盖率。

未裁入本次任务目标的刀盘扫掠并集为 127.1022 m²。若只加入账本的几何内缩并按连续轨迹算，得到 108.6426 m²。实际账本还要根据传感器位姿、刀具反馈、速度、新鲜度及每次作业授权计量，轨迹偏移、重入和坡面姿态也会改变结果。2026 年 11 月 15 日完成 19/47 段的那次运行实际确认了 71.9439 m²。名义扫掠值不构成可达面积上限，也不给历史/新任务记作业量。[逐作业键的计算结果](../../validation/reproduction/b1_nominal_sweep.json)

## 三、从本 checkout 编译 C++ 规划器并核查版本

已有 Jazzy、OMPL、Eigen 和 Boost 开发库时，可以在自己的 checkout 重新编译实际使用的阿克曼连接路径后端。退出兼容库先编译为本机候选文件。

```bash
source optimization_v2/env.sh
optimization_v2/venvs/scene/bin/python optimization_v2/ws/src/task_platform/scripts/build_safe_route_r10.py
bash optimization_v2/three_tasks/build_compat.sh
optimization_v2/venvs/scene/bin/python optimization_v2/three_tasks/doctor.py native
```

`native` 使用正式任务的安全路线加载函数，同时比较重新编译的 OMPL 二进制、C++ 与 Python 生成器源码，以及原路线版本和几何条件。它还独立核对退出库源码、候选二进制及两个实际系统库的原始哈希。相同平台与编译器下，本次独立编译实际复现了两份二进制哈希。编译器或库发生变化时可能得到不同二进制，需要在该版本重新验证。

## 四、编译实际 ROS 动作接口并核查启动条件

下列命令适用于已按 `BUILDING.md` 配置 ROS 2 Jazzy 的 Ubuntu 24.04。它们分别编译项目基础包及产生 ToolTask 动作类型的接口包，之后可以直接读取接口定义。

```bash
source optimization_v2/env.sh
(cd optimization_v2/ws && MAKEFLAGS=-j1 CMAKE_BUILD_PARALLEL_LEVEL=1 colcon build \
  --executor sequential --packages-select mission_interfaces project_baseline \
  --cmake-args -DCMAKE_BUILD_TYPE=Release)
source optimization_v2/env.sh
ros2 interface show mission_interfaces/action/ToolTask
python3 optimization_v2/three_tasks/doctor.py runtime
```

运行前检查会加载场景 Python、ToolTask 类型，检查八个实际用到的 ROS 可执行文件，逐车调用原始 R01 任务准入函数核查所有配置输入，再检查 Gazebo 退出兼容库和当前工作区的 R09 录制前置回执。在开发机上，R10/R12 的仿真应始终通过正常的 `advance.sh` 入口运行。该入口还会校验场景、派生运行脚本和本次实际使用的二进制与配置。doctor 的预检不能替代这一步。

原 R01 ABI 锁把应用动态库放在 `/home/ceihao/robot_project/optimization_v2/three_tasks/build/libr01_shutdown_compat.so`。三个任务配置又绑定了整份锁文件的字节。换目录时，原锁会触发 `SHUTDOWN_SHIM_SCOPE` 或库不存在。若只在锁里改成新目录，库检查可以通过，但三个任务的正式准入均会报 `TASK_INPUT_CHANGED shutdown`。以下命令用原生产验证函数和真实已恢复输入在临时目录复现实验，结束会删除那份临时副本。

```bash
python3 optimization_v2/three_tasks/test_workspace_binding.py
```

原环境可保留已有路径和已核验的库。在独立新机器使用同一路径时，先恢复两套资产、在本机编译、运行上述原生字节校验，再将相同哈希的候选安装到原锁规定位置并重新做实际阶段验收。如果必须使用不同目录，则需要新建本地版本，重建 R01 的退出库锁、三份任务配置的输入哈希和版本，并从 R01 启动/退出案例起实际复验受影响的后继阶段。这项工作还涉及历史准入资源，本文测的是移植条件。发布目录 `validation/` 可查看开发机证据。`R09 ... NOT_RUN` 表示这个工作区仍没有录制入口要求的本地前置回执。

```bash
cd /home/ceihao/robot_project
bash optimization_v2/three_tasks/gui.sh
# 另一个终端进入同一工程后运行
```

浏览器访问 `http://127.0.0.1:8088`。完整复验使用 `R10 test record_spray_full_A1` 或 `R10 test record_mowing_full_B1`，一次只启动一个 Gazebo。独立 checkout 的离线复验和开发机任务实测在交付记录中分别计分。
