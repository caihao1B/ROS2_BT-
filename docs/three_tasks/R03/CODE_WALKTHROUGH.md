# 核心代码逻辑

C++ `optimization_v2/ws/src/task_platform/r03_backend/reeds_shepp.cpp` 接收起终点和转弯半径，调用安装的 OMPL 实现，输出最多五段带符号长度的直线/圆弧原语。长度为负代表倒车；曲率符号仍表达车身方向的转向几何。该后端不宣称碰撞可行，避免把最短运动学路径误作导航路径。

Python `scripts/reeds_r03.py` 将原语按最多 0.10 m 步长积分，保持车身朝向，并按原语划分带方向和停车标记的段。它检查原生求解终点，不使用旧版只支持正长度的采样器。

Python `scripts/planning_r03.py` 负责：读取公开先验 → 版本化任务域 → METIS 分簇 → 点服务图/TSP 或 Fields2Cover 条带 → 整车碰撞检查后的连接 → 工具开关、预计工时、残余几何和配置哈希。地头是全区共享空间，簇边界只是任务归属边界。

Python `scripts/verify_r03.py` 从导出的路径重新计算姿态连续性、曲率、前后档方向、车身包络和区域面积账。规划器返回成功不会直接成为 PASS。`stage_r03.py` 再运行七项测试，将实际输入、输出、后端二进制和代码摘要写入回执。

核心关系：后轴曲率 κ=tan(δ)/L；圆弧积分 dθ=κ·ds，倒车 ds<0；工具中心=后轴位置+R(θ)·工具偏移。工具覆盖只统计 work 段的工具足迹与该簇的交集。后续闭环执行仍需定位、停车反馈和工具成功反馈，不能复用这里的 planned_cut 作为有效作业面积。
